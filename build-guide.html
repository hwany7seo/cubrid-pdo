1. Overview

CUBRID PDO Driver (pdo_cubrid) is the official PDO driver (new PDO("cubrid:...")) for the CUBRID database. The CUBRID CCI library is included as the cci-src git submodule and is built together with the driver, so CUBRID does not need to be installed to build the driver.

PlatformPHPCompilerModule
Linux x86_648.3, 8.4, 8.5 (NTS, ZTS)GCCpdo_cubrid.so (CCI and OpenSSL linked statically)
Windows x648.4, 8.5 (NTS, TS)Visual Studio 2022 (vs17)php_pdo_cubrid.dll + cascci.dll

32-bit platforms and ARM64 are not supported. PHP 8.2 and earlier are not supported; use an earlier driver release for them.

The driver requires the PDO extension of PHP. PDO is built into most PHP builds; when it is a shared module (pdo.so), it must be loaded before pdo_cubrid.

End users usually do not need to build the driver. See the CUBRID manual for installing it with PIE or from the release packages: https://www.cubrid.org/manual/en/11.4/api/pdo.html.

2. Building on Linux

2.1 Requirements

ItemNote
GCC / G++, makeGCC 8 or later is recommended (e.g. gcc-toolset / devtoolset on RHEL-compatible systems).
CMakeUsed to build CCI (3.x recommended).
autoconfRequired by phpize.
PHP development filesphpize and php-config of the target PHP, e.g. php-devel (RHEL) or php8.x-dev (Debian/Ubuntu). The PDO headers (include/php/ext/pdo) must be installed with them.
gitOnly for building from the git repository. The release archive does not need git.

Example (RHEL-compatible): dnf install gcc gcc-c++ make cmake autoconf php-devel
Example (Debian/Ubuntu): apt install build-essential cmake autoconf php8.4-dev

2.2 Getting the source

From the git repository (the cci-src submodule is required):

git clone --recursive https://github.com/CUBRID/cubrid-pdo.git
cd cubrid-pdo
# for an existing clone
git submodule update --init

Or download the source release archive php_pdo_cubrid-<version>-src.tgz from GitHub Releases, which already contains cci-src:

sha256sum -c php_pdo_cubrid-<version>-src.tgz.sha256
tar xzf php_pdo_cubrid-<version>-src.tgz
cd php_pdo_cubrid-<version>-src

2.3 Building with build.sh

build.sh builds the driver out of the source tree in build_linux/<ver>/, so the source tree stays clean and several PHP versions can be built side by side. CCI is built once and shared.

./build.sh <ver> [--php-config PATH] [--install] [--clean]
    ver: 83, 84, 85

./build.sh 84 --php-config /usr/bin/php-config      # -> build_linux/84/modules/pdo_cubrid.so
./build.sh 85 --install                             # also install it and enable it in php.ini
OptionDescription
--php-config PATHphp-config of the target PHP. Default: $PHP_HOME/<x.y>/bin/php-config (PHP_HOME=~/php), otherwise php-config in PATH if its version matches.
--installRun make install and add extension=pdo_cubrid.so (and extension=pdo.so when PDO is not loaded yet) to the php.ini of the target PHP.
--cleanRemove the build directory and build from scratch.

2.4 Building with phpize

The standard PHP extension build also works (in the source tree):

phpize
./configure --with-php-config=/usr/bin/php-config
make
sudo make install

The extension is enabled by default, so --with-pdo-cubrid is not needed. configure builds CCI (cci-src/build_x86_64_release) first, which takes a few minutes the first time.

2.5 Enabling the extension

Add the following to php.ini, or to a file in the additional ini directory (e.g. /etc/php.d/pdo_cubrid.ini or /etc/php/8.4/mods-available/pdo_cubrid.ini):

; only when PDO is a shared module (pdo.so) and not loaded yet
; extension=pdo
extension=pdo_cubrid

Check that it is loaded:

php -m | grep -i pdo_cubrid
php --ri pdo_cubrid

Restart the web server or PHP-FPM after changing the configuration.

3. Building on Windows

3.1 Requirements

  • Visual Studio 2022 with the "Desktop development with C++" workload (MSVC v143, CMake)
  • Git for Windows (the CCI CMake build uses git and awk of Git\usr\bin)
  • Windows PowerShell 5.1 or PowerShell 7

The PHP binaries, the PHP devel packs and the PHP SDK binary tools are downloaded automatically by build_win.ps1 into build_win\downloads, unless existing ones are given with -PhpDir, -DevelPack and -PhpSdk.

3.2 Building with build_win.ps1

.\build_win.ps1 <ver> [-ThreadSafe] [-PhpVersion X.Y.Z] [-PhpDir DIR] [-DevelPack DIR] [-PhpSdk DIR] [-Clean]
    ver: 84, 85

.\build_win.ps1 84                      # PHP 8.4 NTS -> build_win\84-nts\modules\php_pdo_cubrid.dll
.\build_win.ps1 85 -ThreadSafe          # PHP 8.5 TS  -> build_win\85-ts\modules\php_pdo_cubrid.dll
.\build_win.ps1 84 -PhpVersion 8.4.14 -Clean

CCI is built once with CMake as cascci.dll (build_win\cci) and shared by all targets. build_win\<ver>-<nts|ts>\modules contains php_pdo_cubrid.dll and cascci.dll. Run Get-Help .\build_win.ps1 -Detailed for all options.

3.3 Installing the build

  1. Copy php_pdo_cubrid.dll to the ext directory of PHP (e.g. C:\php\ext).
  2. Copy cascci.dll next to php.exe (e.g. C:\php) or to a directory in PATH. Windows does not look for dependent DLLs in the ext directory.
  3. Add extension=pdo_cubrid to php.ini.
  4. The Microsoft Visual C++ 2015-2022 Redistributable (x64) is required; it is installed with the official PHP builds in most cases.

PDO itself is built into php8.dll of the official Windows PHP builds, so only pdo_cubrid needs to be enabled.

4. Testing

The tests need a running CUBRID server (a broker on port 33000 with demodb). Build the driver with ./build.sh <ver> first; the test runners load build_linux/<ver>/modules/pdo_cubrid.so without reading php.ini.

DirectoryRunnerDescription
tests_8xrun_tests.sh / run_tests.ps1PDO driver tests (.phpt, run-tests.php). The tests connect to demodb on localhost:33000.
cd tests_8x
PHP_BIN=~/php/8.4/bin/php ./run_tests.sh

5. Making a release

A release is published as a GitHub release of the tag <version> (without a v prefix), where <version> is PDO_CUBRID_VERSION in pdo_cubrid_version.h. The release assets follow the PIE naming conventions, so pie install cubrid/pdo_cubrid finds them; the same files are used for manual installation.

AssetMade byUsed for
php_pdo_cubrid-<version>-src.tgzscript/release.shLinux: PIE (pre-packaged source), manual build
php_pdo_cubrid-<version>-<8.4|8.5>-<nts|ts>-vs17-x86_64.zipscript/release.ps1Windows: PIE, manual installation
*.sha256both scriptsSHA-256 checksum of each file (sha256sum -c format)

5.1 Linux source archive: script/release.sh

script/release.sh [--ref REV] [--output DIR] [--check [PHP_CONFIG]]

script/release.sh                                   # HEAD
script/release.sh --ref <version> --check ~/php/8.4/bin/php-config
  • The archive is made from a committed revision (HEAD by default) and the cci-src commit recorded in it; uncommitted changes and build outputs are never packaged.
  • The top directory in the archive is php_pdo_cubrid-<version>-src/.
  • In the packaged cci-src (the cci-src repository itself is not changed): build.sh does not stop when git is missing, BUILD_NUMBER holds the full CCI version (e.g. 11.2.0.0040-9965aa8), and win/ is left out.
  • --check extracts the archive into script/release/check and builds it with phpize; ./configure; make as PIE does, then checks that the module loads.
  • Output: script/release/ (ignored by git). The same directory is used by script/release.ps1.

5.2 Windows binaries: script/release.ps1

.\script\release.ps1 [-Targets 84,85] [-Flavors nts,ts] [-PhpSdk DIR] [-OutputDir DIR] [-Clean]

.\script\release.ps1                                # 8.4/8.5 x NTS/TS = 4 zips

Each target is built with build_win.ps1. Each zip contains:

  • php_pdo_cubrid-<version>-<x.y>-<nts|ts>-vs17-x86_64.dll: the extension, named like the zip as PIE requires (PIE installs it as ext\php_pdo_cubrid.dll; rename it when installing by hand)
  • .pdb of the extension, when built
  • cascci.dll (PIE copies it next to php.exe)
  • LICENSE

5.3 Publishing

  1. Update PDO_CUBRID_VERSION in pdo_cubrid_version.h and the release notes, and commit.
  2. Tag the commit: git tag <version>, git push origin <version>.
  3. Run script/release.sh --ref <version> --check on Linux and script\release.ps1 on Windows (from the same tag).
  4. Create a GitHub release for the tag and upload the .tgz, .zip and .sha256 files of script/release including the .sha256 files.
  5. Packagist (cubrid/pdo_cubrid) picks up the new tag through the GitHub webhook. Check it with pie install cubrid/pdo_cubrid:<version>.

To test a release before it is on Packagist (e.g. from a fork), add the repository to PIE:

pie repository:add vcs https://github.com/<user>/cubrid-pdo
pie install cubrid/pdo_cubrid:<version>
pie repository:remove vcs https://github.com/<user>/cubrid-pdo

An extracted source archive can also be installed with PIE without network access:

pie repository:add path /path/to/php_pdo_cubrid-<version>-src
pie install cubrid/pdo_cubrid:*@dev

The source archive asset must be attached to the GitHub release. Without it, PIE falls back to the GitHub source zip, which does not contain the cci-src submodule, and the build fails.
